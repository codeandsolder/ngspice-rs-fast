# LTRA endpoint preparation and ordered history reduction

Issue [#100](https://github.com/codeandsolder/ngspice-rs-fast/issues/100).
Scalar baseline: `14eb2db2dc334903d87c8c900bbd9f43f0e4a38a`.
Initial vector implementation: `aa48956b4e7f7348b386e551d9d6a8d630dd9788`.
Host: Acer, Ryzen 7 4700U (8 cores), rustc
1.102.0-nightly (6905905bb 2026-11-19); managed sccache.

## Architecture

* The sampled history exposes forward/reverse row iteration directly across
  its ring slices, reconstructing at most one split row. No materialized
  contiguous history or additional coefficient buffer is needed.
* Long histories accumulate the six independent port contributions in
  SIMD lanes, using one reverse traversal. The newest, uncoupled RLC
  portion uses only the local two voltage lanes. Each individual sum
  retains the original reverse order, including seeds, skipped zero
  weights, the coupled cutoff and signed-zero behavior. No horizontal
  reassociation or fused multiply-add is used.
* Short histories (<32 samples) use indexed scalar traversal. This avoids
  iterator and SIMD setup costs. For a short RLC history with no coupled
  accepted samples, only the self kernel's divided differences are needed.
* RC endpoint preparation batches four independent lags; the series and
  continued-fraction erfc recurrences have independent lane termination.
  RLC shares Bessel polynomial coefficients between scalar and vector
  evaluators, and shares the large-argument exponential and square root
  across I0/I1. Both retain sequential coefficient differencing and
  chopping; mixed regimes and nonzero chopping use scalar evaluation.
  Transcendental exponentials remain scalar per lane.
* Model/time-grid coefficient sharing and transient load orchestration
  belong to #107, rather than speculative caches in this numerical kernel.
  GPU offload would need to amortize dispatch and data transfer; the
  current CPU path has no new allocation or transfer requirement.

## Isolated coefficient preparation

The original and candidate convolution modules were compiled directly as
Rust modules (not rewritten benchmark expressions) with the same release
optimization and target CPU. Each case used a nonuniform grid of integer
ticks, approximately 1,048,576 evaluated history knots per trial, and
three interleaved baseline/candidate trials. The table reports median
userspace task-clock from `perf stat` in milliseconds. This is not
elapsed simulation time. The per-coefficient signatures were identical.
The initial vector checkpoint uses the same long-history kernels as
the final short-history dispatch.

| Kernel | Knots | Generic old | Generic SIMD | Speedup | Native old | Native SIMD | Speedup |
|---|---:|---:|---:|---:|---:|---:|---:|
| RC | 8 | 42.12 | 40.03 | 1.05x | 40.71 | 38.00 | 1.07x |
| RC | 128 | 232.04 | 110.47 | 2.10x | 227.89 | 89.01 | 2.56x |
| RC | 2,048 | 133.31 | 83.50 | 1.60x | 136.87 | 53.74 | 2.55x |
| RC | 16,384 | 87.52 | 60.84 | 1.44x | 89.27 | 40.65 | 2.20x |
| RLC | 8 | 31.23 | 36.62 | 0.85x | 31.12 | 37.11 | 0.84x |
| RLC | 128 | 27.41 | 23.14 | 1.18x | 26.81 | 23.71 | 1.13x |
| RLC | 2,048 | 59.77 | 38.80 | 1.54x | 57.91 | 36.56 | 1.58x |
| RLC | 16,384 | 92.76 | 55.42 | 1.67x | 87.59 | 50.45 | 1.74x |

The eight-knot RLC regression prompted further interleaved probes. A
simple scalar threshold made it worse and was rejected. A physically
uncoupled, single-kernel specialization instead produced the following
native task-clock results (separate run, so compare within rows):

| Knots | Baseline | General vector checkpoint | Specialized candidate |
|---|---:|---:|---:|
| 8 | 22.46 | 26.03 | 21.10 |
| 16 | 19.76 | 20.33 | 18.54 |
| 32 | 30.85 | 18.27 | 18.14 |
| 128 | 18.11 | 16.14 | 16.21 |

All signatures matched. The final shared scalar endpoint implementation
was also compared directly against the original module for 4,080 RLC
cases per target (generic and native), covering sizes 1–34, both ring
layouts, five delays, four chopping tolerances and three beta values:
all coefficient bits matched, treating NaN payloads as equivalent.

## History reduction and complete transient

`history_reduction_benchmark` compares the scalar indexed reduction with
the production dispatch and asserts exact result bits on RC and RLC
weights, wrapped and unwrapped histories. The initial long-history run
observed approximately 1.6–1.8x native reductions, but later elapsed
measurements fluctuated substantially under competing campaign builds.
The short-history regression in the original vector dispatch motivated
retaining the indexed scalar implementation below 32 samples; no
independent final short-reduction speedup is claimed.

`tests/ltra_simd_bench.rs` includes repeatable RC/RLC coefficient and
complete-transient workloads. For the initial vector checkpoint, all
16 coefficient signatures and both transient signatures matched
the baseline for each of the generic and native release targets.
Both circuits had 1,008 sample times; the time/output digests were
`99e56e9c95cc5891` (RC) and `e3eadb2ef74cc0cc` (RLC).
The wall-time samples varied by several-fold as other builds competed
for the eight cores, so no end-to-end speedup is inferred from them.

## Reproduction

Use the campaign's pinned nightly and managed sccache:

```sh
cargo +nightly test --locked --release --test ltra_simd_bench -- --ignored --nocapture
cargo +nightly test --locked --release --lib history_reduction_benchmark -- --ignored --nocapture
```

For native measurements use Cargo's `--config 'build.rustflags=["-Ctarget-cpu=native"]'`
option. Copy the benchmark integration-test file into a detached baseline
worktree to compare the same grid, coefficients, and transient requests.
For the isolated measurement use the corresponding convolution module
directly, compiling with `rustc -O -C target-cpu=x86-64` and
`-C target-cpu=native` via managed sccache; use `perf stat -e task-clock,cycles,instructions`
and alternate baseline/candidate order.
